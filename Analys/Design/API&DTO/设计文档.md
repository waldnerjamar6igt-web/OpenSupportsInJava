# OpenSupports API & DTO 设计方案

## Goal
基于 BA.md 的业务分析与 Domain Event 建模，设计完整的 RESTful API 端点定义和请求/响应 DTO 结构，作为后端实现的蓝图文件。

## Current context / assumptions

### 项目现状
- **技术栈**: Spring Boot 4.0.8 + MyBatis + MySQL + Lombok + Jakarta Validation
- **包路径**: `com.openSupports.demo`
- **当前状态**: 空壳项目 — DemoApplication.java 已创建，无 Controller/Service/DTO/Model 代码
- **持久化**: MyBatis（非 JPA）
- **会话**: spring-session-jdbc（服务端存储 session）

### 从方法论推导的设计约束（来自 SoftwareEngneer.md + DomainEventImpleInBack-End.md）
1. **架构分层**: Controller → Application Service → Domain Aggregate/Repo；Command Service 无返回值（只发布事件），Search Service 返回数据
2. **DDD 投影**: BA 中的 domain event 直接映射到 Service 方法名；Controller 调用 Service 编排流程
3. **权限角色**: Visitor(0), Customer(User), Supervisor, Staff(L1/L2/L3)，L3=Admin 拥有最高权限
4. **部门隔离**: Staff 的操作受其所属部门和级别约束
5. **MVP 范围**: 先实现业务闭环（用户→工单→回复→管理），知识库和高级搜索暂不纳入首批交付

### 关键假设
- API 统一前缀 `/api/v1`
- 身份验证由中间件处理（Token/Session 校验），API 层只做资源路由和参数校验
- DTO 按场景拆分：CQRS 视角分开（Request DTO / Response DTO / PageResponse DTO）
- 分页格式统一：`{ content: [], totalElements: N, page: N, size: N }`

---

## Architecture / proposed approach

在 `src/main/java/com/openSupports/demo/api/dto/` 下建立 DTO 子包，每个核心域一个子文件夹，采用命名约定：`XxxCreateCmd`（命令）、`XxxUpdateCmd`、`XxxViewResp`（视图）、`XxxListItemResp`（列表项）。Controller 放在 `src/main/java/com/openSupports/demo/api/controller/`，按域拆分子包。所有 API 端点在独立的 blueprint 文件中描述完整契约。

**通用分页容器 (`common/PageResult.java`)**:
```java
package com.openSupports.demo.api.dto.common;

import lombok.Data;
import java.util.List;

@Data
public class PageResult<T> {
    private List<T> content;
    private long totalElements;
    private int page;
    private int size;
    private int totalPages;

    public static <T> PageResult<T> of(List<T> content, long totalElements, int page, int size) {
        PageResult<T> result = new PageResult<>();
        result.setContent(content);
        result.setTotalElements(totalElements);
        result.setPage(page);
        result.setSize(size);
        result.setTotalPages((int) Math.ceil((double) totalElements / size));
        return result;
    }
}
```

**统一错误响应 (`common/ApiError.java`)**:
```java
package com.openSupports.demo.api.dto.common;

import lombok.Data;
import java.time.LocalDateTime;

@Data
public class ApiError {
    private String code;       // 业务错误码，如 EMAIL_ALREADY_EXISTS
    private String message;    // 给用户看的提示
    private LocalDateTime timestamp;

    public ApiError(String code, String message) {
        this.code = code;
        this.message = message;
        this.timestamp = LocalDateTime.now();
    }
}
```

- 关联的 Domain Event

**示例条目**:
```yaml
endpoints:
  - method: POST
    path: /api/v1/auth/signup
    summary: "用户注册"
    description: "访客提交邮箱和密码完成注册"
    roles: [VISITOR]
    request: UserSignupCmd
    response: TokenResp
    preconditions: []
    postconditions: "用户创建成功，会话建立"
    domainEvents:
```

## Risks, tradeoffs, and open questions

### 风险
1. **Jakarta Validation vs Spring Boot 4.0**: Spring Boot 4.0 使用 Jakarta EE 10 注解（`jakarta.validation.constraints`），需确认项目中是否有 `spring-boot-starter-validation` 依赖。pom.xml 目前只有基础的 starter-session-jdbc，没有 validation starter。实现时需要加上依赖。

2. **Multipart 上传 DTO**: `CreateTicketCmd` 和 `AddCommentCmd` 使用了 `MultipartFile`，这需要在 Controller 层做特殊处理（`@RequestBody` + `@RequestParam` 不能混用）。建议在 DTO 中只保留元信息（附件ID或描述），实际上传走单独的 `/api/v1/upload` 端点。

3. **Pagination OFFSET 问题**: BA.md 第 UC-09 和 UC-11 均提到 `($page-1)*10` 硬编码 OFFSET 但 LIMIT 用 `pageSize` 的不一致问题。计划在 `AdvancedSearchCmd` 中明确标注此问题，建议修复为先。

### 取舍
- **不使用 Swagger/OpenAPI 生成**: 用户目标是快速实现 MVP 后端，引入 SpringDoc/OpenAPI 会增加一层复杂度。API 契约以手写 YAML 为主。
- **DTO 不在这里加 Controller 骨架**: 本次任务仅限于 DTO 设计和 API 契约。Controller 是下一阶段的工作。
- **不包含国际化（i18n）**: 用户说只考虑功能实现，不考虑易用性。错误消息直接用中文硬编码在 DTO 的 `message` 字段中。

### 待确认问题
1. **Token 类型**: BA.md 中提到 "session/jwt"，目前用的是 spring-session-jdbc，所以返回的应该是 sessionId 还是自签 JWT？建议先用 sessionId 模式（与现有 session 配置一致）。
2. **CSRF**: BA.md UC-02 提到 CSRF 参数 `csrf_userid`/`csrf_token` 必须匹配。这个是在 API 层做还是交由 Spring Security / 自定义 Filter？需要确认。
3. **文件大小限制**: UC-04 提到"不超过一定大小的文件"，但没给出具体数字。建议默认 10MB/文件，上限写在配置里。
4. **默认排序部门**: UC-04 提到"不可以选择软件默认部门"，默认部门的 ID 如何标识？建议用一个 `is_default=true` 的 flag 字段区分。
